## Findings
1. **should-fix**: `legacy/tests/cr2_overlimit.sh:46-49`. The AC7 baseline run copies `app/` into a temp `CARDDEMO_HOME`, but its result is never checked. If that build fails, `$W/old/TRANSACT.txt` is missing, `b` is empty, and AC7 fails with a misleading message. Add `check "AC7 baseline RC 0" "$(cat "$W/old/RC.txt" 2>/dev/null)" 0` before the compare.
2. **should-fix**: `legacy/tests/cr2_overlimit.sh:10`. Harness output goes to `/dev/null`. If the harness fails, the only sign is `RC` failing with an empty value. Suggest `>"$W/new.log" 2>&1` and print the tail of the log on failure. This only affects how easy failures are to diagnose; the test itself is correct.
3. **nit**: `legacy/tests/cr2_overlimit.sh:31`. The ID check hard-codes `seq 1 52` and `2022071800`. Use `wc -l` of TX for the count, so the check still works if the scenario grows.
4. **nit**: `app/cbl/CBACT04C.cbl:169-171, 207-209, 219, 355, 488-489, 522-573`. The new and edited lines lose the trailing-space padding to column 80 that every other line in the file has. This makes no difference to compilation (it is fixed format and text stays within col 72), but the diff is noisier and the style doesn't match the file. Optional: re-pad to match.
5. **nit**: `app/cbl/CBACT04C.cbl:530-573`. `1400-B-WRITE-FEE-TX` is a near copy of `1300-B-WRITE-TX`, about 30 lines duplicated. That is acceptable for this CR and is the pattern the spec asked for. A shared write paragraph could come later if more fees are added.
6. **nit**: `app/cbl/CBACT04C.cbl:170`. The fee is a hard-coded constant (`VALUE 25.00`), as the spec says (configuration is out of scope). It is worth flagging to Product as a follow-up.

Money/sign handling is fine:
- The compare is signed and strict, so credit balances and balance = limit are not charged.
- The fee is `S9(09)V99` and goes into `S9(10)V99` with no truncation risk at 25.00.
- `WS-TOTAL-FEE` is reset at every control break before `1050` can use it.
- Reading the account or xref abends on error before the fee step runs, so a stale balance can't trigger a fee.

## What a human should look at before merging
- **R1 is still there**: the last account in TCATBAL is never rewritten. If it is over limit in production, the fee transaction is written but the balance never gets it. Raise the separate CR now.
- **R4, ID shift**: every fee uses up one transaction-ID suffix, so the IDs of all later transactions move by +1. Confirm that no downstream consumer depends on the ID positions.
- **R6, reference data**: the production `TRANCATG` KSDS has to be reloaded (`TRANCATG.jcl`) so that `CBTRN03C` reports show "Over-limit Fee". The EBCDIC data was not updated.
- **Expected files**: `legacy/tests/cr2_overlimit/expected/*` were generated by the harness. I spot-checked accounts 1–4 and 50 against the spec and they are right. The script's own assertions (AC3–AC9) don't depend on these files.
