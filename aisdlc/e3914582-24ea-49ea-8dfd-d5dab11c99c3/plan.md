## Test strategy

- **Equivalence (AC1):** `legacy/harness/golden.sh --check`. It covers the CBACT04C stock and
  CBACT04C-after-CBTRN02C scenarios (0 over-limit accounts) and CBTRN02C (untouched).
- **AC5 baseline evidence:** run the scenario once with the baseline program
  (`git stash` / `git show baseline:app/cbl/CBACT04C.cbl`). Record that accounts 02/03 come out byte-equal in
  ACCTFILE, and that their interest records are equal except for TRAN-ID. Quote this in the test report.
- **AC8:** capture the compiler stderr from `run.sh` before and after the change; it must show no new warnings.
- Commands:
  ```
  legacy/harness/golden.sh --check
  legacy/tests/cr2_overlimit.sh
  ```

## Risks

- Fee written at the break changes record order versus the "after interest" hook → golden has no
  over-limit accounts, so golden.sh shows no diff. The order is stated in the spec (rule 7).
- `MOVE SPACES TO TRAN-DESC` in 1300-B could change golden bytes → today's tail is already spaces
  (README quirk); golden.sh proves this.
- Overpunch errors in the hand-built inputs → edit only the balance/limit fields (cols 13-36), and check by
  re-unloading through the harness and reading the TRANSACT amounts.
- F3 hides acct 05's balance → this is intended. The test asserts it explicitly, so a later F3 fix shows up
  as a deliberate expected-file change.
