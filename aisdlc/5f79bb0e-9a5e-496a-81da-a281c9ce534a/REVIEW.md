## Findings

1. **should-fix**: `DefectTest.java:47` (F2), `:55` (F3), `:37` (F1 golden). These tests only read `legacy/golden/*` or `probes/*/expected/*` and never run Java, so they would pass even if the Java code changed. Real coverage comes from `GoldenTest` and `HarnessProbeTest`. *Suggestion:* run `Cbtrn02c` and assert on its output (e.g. F3: the Java `DALYREJS` for `reasons` has `0103` on `…68358X`), or delete them and point to the probe test.
2. **should-fix**: `DefectTest.java:104` / `Cbtrn02c.java:222` (F6). `rejsCloseErrorMessage` is a static helper that production code never calls, so the test checks a string it builds itself. That is a tautology. The close-error paths do not exist in Java at all, because close cannot fail in memory. *Suggestion:* drop the helper and test, and list F6 in the README as "not reproducible: no close errors in the in-memory store". Do not fake coverage.
3. **should-fix**: `Main.java:66`. A malformed `CARDDEMO_CURRENT_DATE` (e.g. `20220718`) silently falls back to the system clock. I confirmed this: it posted `2026-10-12-04.30.43.370000`. In production, a re-run for a business date would be stamped with the wrong date and nobody would notice. *Suggestion:* if the variable is set but its length is not 16 or it does not parse, print to stderr and exit 16.
4. **should-fix**: missing tests from `plan.md` §2. There is no `ZonedTest` covering all 20 sign characters (`GoldenTest.java:44` covers 4 cases), and AC5's `…000000` case is covered only indirectly through golden. *Suggestion:* add a parameterised round-trip over `{A–I}J–R` and the explicit `2022-07-18T00:00Z` timestamp assertion.
5. **nit**: `Main.java:58`. On a `LoadException` the SYSOUT lines already printed (`START…`) are not written to `SYSOUT.txt`, and no dataset is written. This matches the harness, which also writes nothing on a load failure, but say so in the README.
6. **nit**: dead code and readability.
   - `Cbtrn02c.java:141`: `amtRaw` is only used for decoding. Inline it.
   - `:75`: `daly = null` is a redundant initialiser.
   - `:161`: `tcatWork = found;` is overwritten on the next line.
   - `:195-211`: `RuntimeExceptionIO` plus `throws RuntimeExceptionIO`. Let `save()` throw `IOException`, since `run()` already declares it.
   - `Main.java:9`: unused `Instant` import.
   - `GoldenTest.java:46`: `"00000000000".substring(1) + "{"` should be `"0000000000{"`.
7. **nit**: `Cbtrn02c.java:216`. `"00" + status` hardcodes the para 9910 format for the numeric statuses only. That is fine for the 22/23/35 it is called with. A one-line comment would stop someone passing `"9x"` later.
8. **nit**: `Main.java:40`. The `--stock` temp directory is never deleted.

## What a human should look at before merging

- **F5 and F2 are production hazards that were kept on purpose.** TRANFILE is replaced on every run, and debits count as credit headroom (38 rejects instead of 23 on stock data). Both are like-for-like as approved (Q3). Open the follow-up CR now so this module is not deployed as the master-file writer without it.
- **Abend dataset state** (spec §5): on RC 16, Java writes partially updated ACCTFILE and TCATBALF. The harness cannot verify this. Decide whether operations want that, or want no outputs written, as the harness does.
- **Clock fallback** (finding 3). Decide before the job is scheduled in a container.
- Findings 1–2 do not change behaviour, but they inflate the "defects pinned" count reported for AC7. F6 in particular is not really pinned.
